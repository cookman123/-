# 模擬交易沙盒計劃

> 本文件是工作計劃，不是結果。沙盒**不是**本 repo 研究的一部分：不修改任何既有腳本、
> `davis_tw/` 和 `data/` 裡的檔案，不覆寫 `results/` 既有的輸出，不影響
> `results/研究結論總整理.md` 的任何結論。該文件「找不到扣成本、沖掉市場風險後仍存在的
> 可交易 alpha」的結論，沙盒不推翻它。

## 0. 目標與範圍

給一筆虛擬資金，讓任意策略在台股歷史日資料上下單，沙盒負責撮合、扣成本、
檢查風控、記帳、出績效報表。**第一階段不接任何訊號**，只用答案已知的假策略
驗證沙盒本身是對的。

| 做 | 不做 |
|---|---|
| 日頻、只做多、現股 | 盤中、融資融券、放空、當沖 |
| 歷史資料回放 | 接券商或任何真實下單 |
| 策略介面（目標權重） | 任何實際訊號（attention、LSTM、LLM 都是第二階段） |
| 對帳測試 | 參數最佳化 |

## 1. 在本 repo 的位置

本 repo 的腳本平鋪在根目錄，可重用的程式放在套件 `davis_tw/`。沙盒比照 `davis_tw/`，
在根目錄另開一個套件：

```
sandbox/
  __init__.py
  data.py        # 資料介面（抽象）＋本 repo 的 Yahoo CSV 轉接器
  broker.py      # 撮合、成本、台股交易規則
  portfolio.py   # 帳戶、持股、現金、公司行動
  risk.py        # 風控規則
  engine.py      # 主迴圈：策略 → 風控 → 撮合 → 記帳
  strategies.py  # 只有驗證用的假策略
  report.py      # 績效指標與報表
  run.py         # 命令列入口：python -m sandbox.run --help
tests/sandbox/
  conftest.py    # 在暫存資料夾產生小型合成 data/（測試不依賴本機資料）
```

- `sandbox/` **不 import 根目錄腳本**（`davis_tw_train.py` 等），也不 import `davis_tw/`。
  檔案路徑、欄位名稱只出現在 `data.py` 的轉接器裡。價格讀取邏輯會與
  `davis_tw_train.load_price` 重複一份，所以要加一個對照測試：本機有 `data/` 時，
  轉接器讀到的價格要與 `load_price` 完全一致，沒有資料就跳過。
- 依賴只用 `requirements.txt` 已有的 pandas、numpy。測試用 pytest，在 README 註明是
  開發用依賴，不加進 `requirements.txt` 的必要項目。
- 成本參數寫在沙盒自己的設定裡，不讀 `portfolio_backtest.py`、`strategy_spec.py` 的
  常數，避免改沙盒時動到既有的研究結果。
- 執行產物寫到 `results/sandbox/<執行名稱>/`，`.gitignore` 比照現有慣例：只保留
  `report.md`、`config.json` 和摘要 CSV，帳冊與逐日明細不上傳。
- 配合本 repo 的慣例：程式註解與文件用中文；路徑一律用 `pathlib`；CSV 讀寫用
  `utf-8-sig`；命令列入口照其他腳本的寫法，重設 stdout 編碼，讓 Windows 主控台不出亂碼。
- 原始資料（約 13 GB）不在 repo 裡。所有單元測試、作弊測試都只用 `conftest.py` 產生的合成資料，
  在 CI 或沒有資料的機器上也能跑。0050 對帳等真實資料測試，沒有資料就跳過。

## 2. 資料

### 2.1 來源（都在 `data/` 底下，需先照 README 用爬蟲建好）

| 用途 | 檔案 | 說明 |
|---|---|---|
| 存活股日資料 | `stocks/<代號>/price/yahoo_<代號>_<年>.csv` | Yahoo，`date, open, high, low, close, volume`；只有上市（`.TW`），沒有上櫃 |
| 價格修正表 | `price_fixes.csv`（repo 內附） | 222 筆漏調整、錯價的修正係數 |
| 下市股日資料 | `delisted/price/<代號>.csv` | 證交所 STOCK_DAY，**原始價** |
| 除權息 | `corp_actions/exright.csv` | `date, code, kind, prev_close, ref, cash, stock_per_1000, split` |
| 減資 | `corp_actions/reduction.csv` | `date, code, prev_close, ref, reason` |
| 0050、ETF、指數 | `market/<代號>.csv` | 與 `TWII.csv` 同欄位 |
| 交易日曆 | `market/TWII.csv` 的日期 | 本 repo 沒有獨立的交易日曆檔 |
| 時點正確的選股範圍 | `market/turnover_rank.csv` | `universe_pit.py` 產生的近 60 日平均成交金額 |

### 2.2 價格基準：要先還原成原始價

撮合必須用**原始價**，也就是真實能成交的價格和真實的漲跌停價。但本 repo 的
Yahoo 價格是**分割調整價**：配股和減資往回調整，現金股利不調整（見
`corp_actions.py`、`adjust_delisted.py` 的說明）。直接拿來撮合會有三個錯：

- 早年的價位被縮小，整股 1000 股的金額和升降單位都會錯。
- 配股不會增加持股數，只靠調整價吸收。這跟 §4.4 的帳冊記法衝突。
- 除權息日的漲跌停基準是參考價，不是前日收盤。

轉接器的做法：

1. 讀 Yahoo 逐年檔，去掉停牌補值的假列（`volume <= 0` 且 OHLC 全等），套用
   `price_fixes.csv`，跟 `load_price` 的處理相同。
2. 用 `exright.csv` 的 `split` 和 `reduction.csv` 的 `prev_close / ref`，把**事件日之前**
   的價格乘回分割比、成交量除回分割比，還原成原始價。這是 `adjust_delisted.py` 的
   反向操作。
3. 下市股本來就是原始價，不需要第 2 步。

**驗證**：`exright.csv` 的 `prev_close` 是證交所公布的原始前日收盤。還原後，每個
除權息事件前一日的收盤價都要與它相符，誤差超過一個升降單位的事件要列出來。這一項
放進 M0 的完成標準。`price_fixes.csv` 裡標為「Yahoo 未調整」的事件，要確認不會
被還原兩次。

### 2.3 選股範圍與下市

- 資料視圖在 t 日只列出 t 日當時有交易的股票，**包含之後才下市的股票**。不能只用
  `data/stocks/` 的存活股，否則就是本 repo 結論文件裡記錄過的生存者偏誤。
- 持股下市時，以最後交易日的收盤價強制轉成現金，帳冊記 `delisted`。這是近似：
  實際上下市前可能有一段只能賣、不能買的期間。
- `turnover_rank.csv` 只當策略可以查的資料，沙盒本身不篩選股票。

### 2.4 本 repo 沒有的資料

- **處置股**：沒有資料，§4.2 的 `disposition` 標記第一版不做。
- **上櫃股**：沒有日資料，沙盒第一版只有上市股和 `market/` 裡的 ETF。
- **ETF 名單**：證交稅 0.1% 只適用 ETF，第一版以 `fetch_index_targets.py` 的
  `TARGETS` 當名單，寫死在沙盒設定裡。

`exright.csv` 已經分別記錄每股現金股利和每千股配股，所以 §4.4 的公司行動直接做
精確版。

## 3. 時序（防偷看未來）

```
t 日收盤後：策略只能看到 ≤ t 的資料 → 回傳目標權重
t+1 日開盤：沙盒以 t+1 開盤價撮合
t+1 日收盤：以收盤價評價淨值
```

- 策略拿到的是唯讀的資料視圖，查詢 > t 的資料直接報錯，不是回傳空值。
- 成交價時點做成設定（`next_open` 預設、`next_close` 可選）。

## 4. 撮合規則

### 4.1 單位
- 預設整股（1000 股），目標股數向下取整；零股做成開關，預設關。
- 現金不足時依比例縮單，不允許負現金。

### 4.2 成交與拒單
每一筆拒單都寫入帳冊並附原因，不靜默略過。

| 情況 | 處理 |
|---|---|
| 當日無價格（停牌、無成交） | 拒單：`no_price` |
| 買進且開盤即漲停鎖死 | 拒單：`limit_up_locked` |
| 賣出且開盤即跌停鎖死 | 拒單：`limit_down_locked` |
| 處置股期間 | 第一版照常成交但標記 `disposition`，報表另計 |

「鎖死」的近似判準：`open == high == 漲停價`（跌停反之）。漲跌停價由前日收盤
（除權息日改用參考價）乘以漲跌幅上下限，並依升降單位取整。漲跌幅在 2015-06-01
之前是 ±7%，之後是 ±10%；本 repo 的資料從 2010 年起，兩段都會用到。這是日資料
下的近似，盤中是否打開無法得知。

### 4.3 成本
| 項目 | 預設值 | 說明 |
|---|---|---|
| 手續費 | 0.1425% × 折數，預設 6 折 | 買賣都收；折數可調 |
| 手續費下限 | 每筆 20 元 | **待確認**：各券商不同 |
| 證交稅 | 股票 0.3%、ETF 0.1% | 只在賣出收；ETF 名單見 §2.4 |
| 滑價 | 20 bp | 買價上調、賣價下調 |

本 repo 既有的回測用的是另一組數字：`strategy_spec.py` 是手續費 3 折，
`portfolio_backtest.py` 的 `COSTS` 有全額、6 折、3 折三組，兩者都沒有滑價和手續費下限。
沙盒的參數是獨立設定（§1），所以要跟既有結果對照時，要先把沙盒的參數設成跟對方
一樣（3 折、滑價 0、無下限）再比，不能直接拿預設值的結果去比。

### 4.4 公司行動
依 `data/corp_actions/` 的兩個檔案，在事件日開盤前、撮合之前處理。持股以前一個交易日
收盤後的股數為準：

| 事件 | 依據 | 帳冊處理 |
|---|---|---|
| 現金股利 | `exright.csv` 的 `cash`（每股元） | 入帳 `股數 × cash` 的現金 |
| 股票股利 | `exright.csv` 的 `stock_per_1000` | 股數增加 `股數 × stock_per_1000 / 1000`，不足 1 股的部分以參考價折成現金 |
| 減資 | `reduction.csv` 的 `prev_close / ref` | 股數乘以 `prev_close / ref`，不足 1 股的部分以參考價折成現金 |

每一筆都寫進帳冊，類型分別記為 `cash_dividend`、`stock_dividend`、`reduction`。

近似之處（都記在報表的限制段落）：

- 股利在除權息日入帳。實際發放日通常晚幾週，這段期間的現金其實還不能動用。
- 退還股款的現金減資，`reduction.csv` 拆不出退還的現金。這跟 `adjust_delisted.py`
  的限制相同，只能照價值保持處理。
- 現金增資的認購權不處理。

## 5. 風控（寫死在程式，不交給策略）

- 單一個股權重上限（預設 10%）
- 總曝險 ≤ 100%（不融資）
- 單日淨值跌幅超過門檻（預設 5%）→ 當日起停止新開倉，只允許減倉
- 策略回傳的權重有 NaN、負值或總和 > 1 → 整筆拒絕並記錄

## 6. 策略介面

```python
class Strategy(Protocol):
    def generate(self, date: pd.Timestamp, view: DataView) -> dict[str, float] | None:
        """回傳 {代號: 目標權重}，未列出的持股視為目標 0；回傳 None 表示不調整。"""
```

`None` 和 `{}` 不同：`{}` 是全部賣光，`None` 是維持現有持股。買進持有這類策略
如果每天都回傳同一組權重，價格一動、取整後的目標股數就會變，每天都會產生零碎的
買賣；所以不想調整的日子要回傳 `None`。

沙盒自行把目標權重換算成買賣股數。目標金額以成交當下的淨值計算：開盤成交時
持股用當日開盤價評價，沒有開盤價的用前一日收盤價。第二階段接 attention、LSTM 或 LLM 時，
都只是另一個 `Strategy`。

## 7. 驗證（第一階段的完成標準）

| 測試 | 預期 |
|---|---|
| 什麼都不做 | 淨值逐日恆等於初始資金 |
| 買進持有 0050，成本設為零 | 與 0050 含息總報酬的差距 < 0.1%（全期） |
| 買進持有 0050，成本照算 | 差距等於一次買進成本，可逐項對帳 |
| 每日隨機調倉 | 長期報酬 ≈ 等權大盤 − 成本；明顯正報酬視為 bug |
| 作弊策略（讀取 t+1 價格） | 資料視圖報錯 |
| 會計恆等式（每日） | 現金 + 持股市值 = 淨值；累計成本 = 帳冊逐筆加總 |
| 漲跌停、停牌的人工案例 | 依 §4.2 拒單，原因正確 |

全部通過之前，沙盒產出的任何報酬都不得被引用。
